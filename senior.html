AI造物家 移动机器人全栈工程营

12天，从一句 Prompt 到一台会跑、会看、会响应的智能机器人

01

课程对象

高一至高二，适合愿意把 AI、代码、硬件和产品表达放到同一个项目里验证的学生。

02

时间

12 天，完成从真实需求、结构打样、控制开发到技术答辩的闭环。

03

教育落点

连接信息科技、通用技术、研究性学习和校内科创项目，不把大学课硬塞给高中生。

04

AI 工作流

说清问题 → 约束输出 → 生成草案 → 实物验证 → 记录取舍 → 迭代发布。

05

人机分工

AI 负责生成草案和代码片段，学生负责目标、约束、机理解释、测试和最终取舍。

06

工程主线

移动底盘、电机控制、传感器、网页控制、AI 视觉语音、数字孪生和测试报告。

07

闭环验证

Prompt、仿真、实测、故障日志、Token 记录和复盘持续回流。

08

产出

实物机器人、控制网页、开源仓库、技术报告、演示视频和个人 AI 助手 Skill。

2.4 / Senior Program

AI造物家：移动机器人全栈工程营

课程不追求概念堆叠，而是让学生用 AI 把一个可运行、可解释、可复盘的移动机器人项目做出来。

中国教育实际

面向高中阶段的时间、知识基础和升学材料要求设计。内容对接信息科技、通用技术、研究性学习、综合实践、校内创新项目和科技社团，强调过程证据，不承诺竞赛或申请结果。

北京与宁波语境

北京更关注 AI 通识、科创实践和高校资源衔接；宁波有港口物流、智能制造、园区服务和机器人应用场景。课程把这些转成校园巡检、自动配送、导览服务和无障碍辅助等可做任务。

新工科方法

不把机器人拆成孤立知识点，而是按真实工程链条推进：问题定义、系统架构、软硬件开发、测试验证、文档开源和路演答辩。每一步都有交付物和评价标准。

一句话定位：AI 负责加速生成，学生负责提出问题、解释原理、验证现实、完成交付。

02 / Capability Map

能力目标

用一个项目同时训练 AI 全栈开发工程师和 AI 产品经理的核心判断。

1

AI 产品经理

能把真实场景转成 PRD、用户流程、功能优先级、验收指标和风险清单。

2

软硬件取舍

能看懂底盘、电机、传感器、主控板、BOM 成本和交互体验之间的关系。

3

AI 全栈开发

覆盖前端控制台、接口协议、MQTT/WebSocket、AI Agent、嵌入式固件和数据日志。

4

机器人功能

完成移动控制、避障、视觉/语音指令、路径任务、数字孪生和异常回退。

5

学术诚信

保留 Prompt、Token、Git Commit、测试数据和修改记录，证明不是复制 AI 答案。

03 / 12-Day Program

12 天高中课程方案

每天按“任务、工具、证据、复盘”推进，保证学生知道自己做了什么、为什么这样做、哪里由 AI 辅助、哪里由自己判断。

主题 上午内容 下午内容 核心工具 交付产出
1 真实场景与问题定义
  • 说明课程与高中信息科技、通用技术、研究性学习、综合实践和校内科创项目的关系。
  • 从校园、社区、园区和城市服务中选择可做场景：巡检、配送、导览、陪伴、无障碍辅助等。
  • 学习“用户-场景-痛点-约束-可验证指标”模板，把一句想法改成可开发需求。
  • 双人组建项目小队，明确产品、全栈、嵌入式、结构和测试角色。
  • 用 AI 扩展案例和问题清单，学生核验来源、删除不可实现或没有价值的方向。
  • 确定项目边界：场地大小、载重、续航、避障距离、响应时间、预算和安全限制。

2 产品架构与AI提问
  • 训练 Prompt 基本格式：目标、背景、输入、约束、输出格式、验收标准和拒绝条件。
  • 用 AI 产品经理视角拆解软硬件：用户流程、功能优先级、BOM 成本、交互体验和风险。
  • 把机器人拆成底盘、传感器、主控、网页控制、AI Agent、数据日志和数字孪生模块。
  • 确认 PRD v1.0，画出系统架构图和接口草案。
  • 初始化 GitHub/Gitee 仓库，建立 Prompt、代码、测试、文档和 Token 记录目录。
  • 搭建项目主页骨架，预留控制台、摄像头、状态面板和 3D 视窗位置。
 VSCode / GitHub / Gitee / Mermaid / 飞书看板 / Prompt 模板 PRD v1.0、系统架构图、Agent 任务树、仓库脚手架、首次 Commit
3 底盘结构与制造约束
  • 实验室安全培训。
  • 学习为制造而设计：孔位、公差、重心、走线、传感器视场、维修空间和外观一致性。
  • 让机械 Agent 生成 2-3 个底盘方案，学生用决策矩阵比较稳定性、成本、重量和可加工性。
  • 通过 sophicar.com 与 Fusion 360 网页端进行移动机器人参数化设计。
  • AI 辅助生成安装支架、传感器位和外壳草案，学生检查孔位、装配顺序和线束路径。
  • 导出可加工文件，完成第一版底盘和外壳打样准备。
 sophicar.com / Fusion 360 / Tripo 3D / DFM 检查表 STL/STEP 文件、结构决策矩阵、DFM 检查表、设计变更记录
4 数字制造与BOM
  • 根据 CAD 文件设置切片、材料、加工时间和支撑方案。
  • 理解 3D 打印、激光切割和手工装配会带来的误差，提前预留调整空间。
  • 用 BOM 表把电机、轮子、主控、传感器、线材、紧固件和备件列清楚。
  • 加工底盘、外壳和传感器支架，完成初版物理装配。
  • 用 AI 辅助核算成本和替代料，学生决定哪些地方省钱、哪些地方不能省。
  • 记录加工偏差并回写到结构文件。
 Cura / PrusaSlicer / 3D 打印机 / 激光切割机 / BOM Agent 物理底盘 v1、BOM 表、制造日志、加工偏差记录、成本取舍说明
5 嵌入式与底层控制
  • 认识 ESP32-S3、供电、电机驱动、PWM、编码器、I/O 引脚和通电安全。
  • 让 AI 生成引脚表、接线检查表和控制代码草案，学生逐行解释关键逻辑。
  • 建立“AI 生成可以用，学生必须解释清楚才能烧录”的规则。
  • 在 Wokwi 中先跑通前进、后退、转向、停止和急停逻辑。
  • 烧录到物理底盘，完成第一次直线、转向和速度控制。
  • 把失败现象写成“现象-可能原因-验证方法-修正结果”的调试记录。
 ESP32-S3 / Wokwi / VSCode / Arduino / 万用表 引脚表、Wokwi 仿真、底层控制固件、第一次运动测试日志
6 运动学与传感器
  • 用高中可理解的方式推导双轮差速或麦克纳姆轮的速度、转向和轮速关系。
  • 学习超声波、IMU、编码器、摄像头的作用、采样频率、误差来源和适用边界。
  • 设计机器人状态机：待机、手动、自动、避障、错误、急停。
  • 接入传感器并完成基本读数，检查异常值和噪声。
  • 用实测距离、时间、角度和日志校准速度、转向和避障参数。
  • 完成线束整理，给每条线和接口贴标签，降低后续调试成本。
 MaixCAM-Pro / IMU / 编码器 / 超声波 / 逻辑分析仪 运动学说明页、FSM 状态图、传感器读数表、避障测试日志
7 AI全栈控制台
  • 从 AI 全栈开发工程师视角拆分前端页面、接口协议、通信网关、机器人固件和数据日志。
  • 定义控制端需求：按钮、摇杆、状态灯、摄像头区域、日志面板、急停和错误提示。
  • 设计 MQTT/WebSocket Topic、JSON 字段、单位、取值范围和安全回退。
  • 用 Vibe Coding 生成 HTML/CSS/JavaScript 控制网页，学生检查交互和状态反馈。
  • 把网页和物理底盘通过 MQTT/Wi-Fi 打通，记录延迟、丢包和异常动作。
  • 补齐接口文档和安全停机规则。
 HTML / CSS / JavaScript / MQTT.js / WebSocket / Chrome DevTools 控制网页源码、接口说明、无线控制演示、延迟与丢包测试表
8 视觉语音与AI动作协议
  • 学习 VLM、YOLO、语音输入和本地摄像头在机器人里的真实作用。
  • 把“帮我去门口”“看到红色障碍物停下”等自然语言任务改写成机器人可执行的动作 JSON。
  • 规定安全边界：最大速度、禁止动作、失败回退、断网策略和人工接管。
  • 跑通“语音/文本/画面输入 → AI 解析 → JSON 指令 → ESP32 执行”的链路。
  • 用小测试集记录识别准确率、响应延迟、错误动作和人工纠正次数。
  • 把 AI 输出错误的案例写入反例库，作为后续迭代依据。
 Qwen VLM / DeepSeek-VL / YOLO / MaixCAM-Pro / Web Speech API / MQTT 动作 JSON 协议、VLM Prompt、端云控制代码、准确率和延迟测试表
9 数据面板与数字孪生
  • 把数字孪生定义为“可观察、可调试、可解释”的数据面板，而不是炫技动画。
  • 学习坐标系、比例尺、位姿、速度、传感器数据和时间戳的基本关系。
  • 让 AI 生成 Three.js 场景草案，学生校准模型比例和场地坐标。
  • 把物理车速度、姿态、传感器读数同步到网页。
  • 用图表展示测试数据，定位延迟、漂移和异常点。
  • 实现网页目标点或滑块反向控制实体车，完成虚实联动演示。
 Three.js / Chart.js / WebSocket / MQTT / 遥测 Agent 数字孪生网页、遥测数据日志、虚实联动协议、异常数据分析页
10 路径任务与场景验证
  • 围绕 Day 1 选定场景设计可执行任务，例如校园巡检、定点配送、AI 导览或无障碍辅助。
  • 画出简化场地地图、关键点、障碍物、任务路线和失败条件。
  • 对比手动控制、规则路径、AI 规划三种方案的优缺点。
  • 跑通 1 条完整任务链：发出任务、执行路线、避开障碍、记录结果、回到初始状态。
  • 做 5-10 次重复测试，统计成功率、平均耗时、失败原因和改进项。
  • 根据测试数据调整结构、速度、避障阈值或交互提示。
 OpenCV / YOLO / MQTT / 测试场地 / 飞书表格 场景任务脚本、路径测试报告、成功率统计、最终优化清单
11 系统联调与作品集
  • 开展全系统压力测试：断网、弱光、障碍物、低电量、线松动、传感器误差和误触发。
  • 建立 Bug 清单，按严重程度排序，先解决会影响安全和演示稳定性的问题。
  • 整理 AI 使用记录，补齐每次 Prompt、输入 Token、输出 Token、学生修改和验证结果。
  • 整理 README、系统架构图、BOM、代码注释、测试报告、演示视频脚本和路演 PPT。
  • 完成个人 AI 助手 Skill 文档，说明角色、输入输出、能力边界、禁用行为和验证规则。
  • 准备离线演示方案，确保没有网络或 AI 服务时仍能展示核心功能。

12 路演答辩与后续路径
  • 进行“5 分钟技术路演 + 5 分钟 Q&A”：问题、方案、架构、实测数据、失败与改进。
  • 现场演示实物机器人、网页控制台、AI 指令链路和数字孪生数据面板。
  • 评审查看代码仓库、Prompt/Token 记录、测试报告和学生个人贡献说明。
  • 进行企业参访或工程师讲座，了解机器人、智能制造和 AI 全栈岗位的真实分工。
  • 给出后续迭代建议：校内创新项目、Maker/Hackathon、白名单赛事、科研启蒙或作品集整理。
  • 完成个人复盘：AI 帮了什么、AI 没帮上什么、自己下一步要补什么。
